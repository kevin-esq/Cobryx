# ADR-001: Event-Driven Loan Snapshots

## Status
Accepted

## Context
Calculating the state of a loan (principal, interest, fees, DPD) directly from the ledger requires multiple joins and aggregations, which degrades performance for operational queries (dashboards, collections).

## Decision
Implement a snapshot model (`LoanBalanceSnapshot`) generated by Domain Events (Payment, Accrual, StatusChange, Disbursement).

## Consequences

### Pros
- O(1) reads for current state
- Independence from the transactional ledger
- Scalable to millions of loans
- Support for point-in-time historical reporting

### Cons
- Increased storage usage
- Requires maintaining eventual consistency

## Alternatives Considered
- Direct queries to the ledger (rejected due to computational cost)
- Materialized Views (rejected due to less control and flexibility)
